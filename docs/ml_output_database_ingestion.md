## 1. Source Telemetry Contract

The ingestion service reads `outputs/jobs/<job_id>/hazard_telemetry.json` generated by `src/detection/runner.py`. Each telemetry item contains:

```json
{
  "hazard_id": 18,
  "frame_logged": 624,
  "timestamp_sec": 21.52,
  "latitude": 22.308145,
  "longitude": 73.18162,
  "class_name": "waterlogging",
  "risk_level": "CRITICAL",
  "severity_score": 100,
  "relative_depth_drop": 0.0,
  "area_coverage_pct": 87.57,
  "mask_pixels": 453963.5,
  "evidence_file": "hazard_18_CRITICAL.jpg"
}
```

## 2. Four-Class Mapping Contract

The canonical class mapping maps ML detection labels to PostgreSQL `IncidentType` enums:

| ML Class String | Database `IncidentType` Enum | Recommended Action |
| :--- | :--- | :--- |
| `waterlogging` | `WATERLOGGING` | Deploy high-capacity mobile dewatering pump to clear water accumulation. |
| `pothole` | `POTHOLE` | Apply cold mix asphalt patch and set up warning cones. |
| `drainage_overflow` | `DRAINAGE_OVERFLOW` | Deploy excavator to clear culvert silt and trash blockage. |
| `damaged_footpath` | `DAMAGED_FOOTPATH` | Inspect footpath slab damage and install barrier tape. |

Unrecognized class names trigger a `ValueError` during validation.

---

## 3. Severity Normalization & Priority Mapping

### 3.1 Severity Conversion
ML telemetry outputs severity scores on a $0 - 100$ scale. Backend `Incident.severity_score` requires a $0.0 - 10.0$ scale with a database check constraint (`chk_incident_severity_range`).

$$\text{backend\_score} = \text{round}\left(\frac{\text{ml\_score}}{10.0}, 2\right)$$

- Boundary validation: Enforces $0.0 \le \text{backend\_score} \le 10.0$. Scores $<0$ or $>100$ raise a `ValueError`.

### 3.2 Priority Mapping
| Condition | Database `PriorityLevel` |
| :--- | :--- |
| $\text{ml\_score} > 70$ OR `risk_level` == `"CRITICAL"` | `P1` |
| $\text{ml\_score} > 40$ OR `risk_level` == `"HIGH"` | `P2` |
| Otherwise | `P3` |

## 4. Entity Mappings & Spatial Geometry

### 4.1 `Incident` Record
- `incident_code`: `INC-<job_id[:8].upper()>-<hazard_id>` (e.g. `INC-PHASE11A-18`)
- `status`: `IncidentStatus.DETECTED`
- `zone_id`: Resolved via `zone_id` parameter or default zone `EC-01`
- `started_at`: UTC timestamp

### 4.2 `Detection` Record
- `detection_type`: ML class string
- `confidence`: $0.95$ default
- `frame_number`: `frame_logged`
- `detection_metadata`: JSON payload (`timestamp_sec`, `mask_pixels`, `area_coverage_pct`, `relative_depth_drop`, `risk_level`, `job_id`, `hazard_id`)

### 4.3 `Evidence` Record
- `evidence_type`: `EvidenceType.IMAGE`
- `file_path`: `outputs/jobs/<job_id>/evidence/<filename>`
- `is_primary`: `True`
- Asset check: Record is created **only if the image file exists on disk**. Also copied to `outputs/evidence/<job_prefix>_<filename>` for fallback static serving compatibility.

### 4.4 Spatial Mapping (PostGIS POINT)
- Coordinates are stored as GeoJSON Point `[longitude, latitude]` (SRID 4326).
- If latitude/longitude are `None` or `0.0`: `location` is set to `None`, and `missing_gps` counter is incremented in ingestion summary.

---

## 5. Idempotency & Job-Scoped Identity

- **Natural Key**: Combination of `job_id` and `hazard_id`.
- **Deterministic Code**: `INC-<job_id[:8].upper()>-<hazard_id>`
- **Behavior**: If `ingest_job_results` is executed multiple times for the same job:
  - Existing incidents are matched via `incident_code` and skipped.
  - Returns `incidents_created = 0` and `skipped = N`.
  - Database row count remains completely unchanged.
- **Schema Safety**: Implemented using existing `Incident.incident_code` unique constraint without requiring any Alembic database migrations.

---

## 6. Transaction Behavior & Job Lifecycle Integration

1. Ingestion of each hazard is wrapped in an atomic database transaction (`Incident` + `Detection` + `Evidence`).
2. `ProcessingJobManager` invokes `ingest_job_results()` upon zero exit code of runner subprocess.
3. Job status transitions to `COMPLETED` **only after both ML processing and DB ingestion succeed**.
4. If ML succeeds but DB ingestion fails: job status transitions to `FAILED` with error message `"ML completed successfully, database ingestion failed: <error>"`.
