## Executive Summary

**CivicPulse** is a working end-to-end AI-assisted civic monitoring and response platform designed to automate civic infrastructure triage during monsoon seasons.

The platform addresses severe urban challenges—specifically **waterlogging inundation**, **pothole road degradation**, **damaged footpaths**, and **drainage overflows**—by transforming raw aerial drone surveillance footage and flight telemetry into an operational response workflow:

```text
  Raw Drone Video + SRT Flight Information
                     │
                     ▼
  AI Vision Pipeline (YOLOv8 + ByteTrack + MiDaS)
                     │
                     ▼
  Severity & Urgency Scoring (High / Medium / Low)
                     │
                     ▼
  Automated PostGIS / PostgreSQL DB Ingestion
                     │
                     ▼
  Municipal Triage & Human Review (New → Verified)
                     │
                     ▼
  Field Team Assignment & Repair (Work in Progress)
                     │
                     ▼
  Follow-up Inspection & Verification (Resolved)
                     │
                     ▼
  Operational Analytics & Issue Map
```

## Operational Workflow & Lifecycle State Machine

Incidents progress through a strict, audited state machine:

```text
               New (DETECTED)
               /            \
       Verified (VERIFIED)   Rejected (REJECTED)
            │
       Assigned (ASSIGNED)
            │
  Work in Progress (IN_PROGRESS)
            │
  Needs Follow-up (RE_INSPECTION)
            │
       Resolved (CLOSED)
```

1. **New (`DETECTED`)**: Automatically generated by the AI drone video analysis engine.
2. **Verified (`VERIFIED`)**: Confirmed as a genuine issue by an operator.
3. **Rejected (`REJECTED`)**: Dismissed as a false positive or optical reflection with logged rationale.
4. **Assigned (`ASSIGNED`)**: Allocated to a municipal repair team with recommended action.
5. **Work in Progress (`IN_PROGRESS`)**: Field repair team is actively working on-site.
6. **Needs Follow-up (`RE_INSPECTION`)**: Repair work completed; queued for follow-up drone inspection.
7. **Resolved (`CLOSED`)**: Follow-up inspection can be used to confirm the repair and mark the issue as resolved.

## Technology Stack

### Backend & Machine Learning
- **Language**: Python 3.11+
- **Web Framework**: FastAPI (Asynchronous REST API)
- **Database**: PostgreSQL with PostGIS spatial extension
- **ORM & Migrations**: SQLAlchemy 2.0, Alembic
- **Computer Vision**: PyTorch, OpenCV, YOLOv8 (Segmentation), ByteTrack (Tracking), MiDaS (Monocular Depth)

- **Testing**: Pytest, Httpx, AnyIO

- **Framework**: React 18, TypeScript, Vite
- **Styling**: Tailwind CSS, Lucide React icons
- **Geospatial Mapping**: `@vis.gl/react-google-maps`
- **Charts & Data Viz**: Recharts
- **Testing & Quality**: Vitest, TypeScript compiler (`tsc --noEmit`)

## Local Setup & Quick Start

### 1. Backend Setup

```bash
# Clone the repository
git clone https://github.com/IndependentSalt69/Not-So-Smart_ELCIA.git
cd Not-So-Smart_ELCIA

# Create and activate Python virtual environment
python -m venv .venv

# On Windows (PowerShell):
.\.venv\Scripts\Activate.ps1
# On Linux/macOS:
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Run database migrations
alembic upgrade head

# Start FastAPI application server
python -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000
```

### 2. Frontend Dashboard Setup

```bash
# Navigate to dashboard directory
cd dashboard

# Install dependencies with legacy peer deps workaround
npm install --legacy-peer-deps

# Start local development server
npm run dev
```

The dashboard will launch locally at `http://localhost:5173`.

## Developer Reference

### API Reference

#### Incidents API
- `GET /api/v1/incidents/`: Query incidents with optional filters (`zone_id`, `incident_type`, `status`, `priority`, `min_severity`).
- `POST /api/v1/incidents/`: Create a new incident.
- `GET /api/v1/incidents/{id}`: Retrieve detailed metadata for a specific incident.
- `PATCH /api/v1/incidents/{id}`: Update incident properties.
- `PATCH /api/v1/incidents/{id}/status`: Advance incident lifecycle status and log audit history.

#### Evidence & Processing API
- `POST /api/v1/processing/jobs`: Submit raw video and SRT log to trigger real asynchronous ML processing.
- `GET /api/v1/processing/jobs/{job_id}`: Poll job status, progress percentage, and results URL.
- `GET /api/v1/incidents/{id}/evidence`: Retrieve evidence frame JPEGs and annotated video clips.

#### Analytics API
- `GET /api/v1/analytics/summary`: KPI summary metrics (active count, critical count, resolution time).
- `GET /api/v1/analytics/trends`: 7-day daily issue counts for Waterlogging, Potholes, Damaged Footpath, and Drainage Overflow.
- `GET /api/v1/analytics/zones`: Per-zone incident breakdown by urgency level.
